# N2.3B2 follow-on — exact reference-space hit-test invariant

This narrow technical correction is based on the already committed
N2.3B2 viewport change at 6305b278aec93051232e4cecf10b4b4a14a35287.

## Problem

The native Canvas pointer path uses reference-space distances and
circular regions whose radius is a fraction of the 600-unit reference height.
The older hitNormalized compatibility API instead measured Euclidean
distance on normalized x/y coordinates. Since the reference artwork is
1000 wide and 600 high, that method applied physically different radii
along horizontal and vertical axes.

For pellicle landmark (0.30, 0.27) and radius fraction 0.087:
the sample (0.37, 0.27) was inside the old normalized circle but
70 reference units from the center, outside the native pixel hit
circle of radius 52.2. This could produce contradictory results
between pure-Kotlin validation and real Compose touches.

## Corrective rule

Both hitCanvas and hitNormalized now delegate to one pure Kotlin
hitAtReference operation in the same 1000x600 drawing space.
The existing native Canvas pixel-selection behaviour and drawing
transform are unchanged.

Add deterministic JVM tests comparing normalized-versus-pixel
selection for every organ at five radial distances and four Canvas
sizes. Specifically forbid the documented false positive.
